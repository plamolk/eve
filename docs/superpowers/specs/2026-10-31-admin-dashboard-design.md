# หน้าดูข้อมูลแอดมินแบบครบถ้วน — Design Spec

- วันที่: 2026-10-31
- สถานะ: รอผู้ใช้ตรวจ
- ต่อยอดจาก: `docs/superpowers/specs/2026-10-30-blood-mobile-survey-backend-design.md` (ข้อห้ามและข้อกำหนดทั้งหมดของ spec นั้นยังใช้อยู่)
- branch: `feature/survey-backend`

## 1. เป้าหมายและเกณฑ์สำเร็จ

**ผู้ใช้ขอ:** หน้า frontend สำหรับดูข้อมูลที่บอกได้ว่ามีคนตอบกี่คน มีความคิดเห็นอะไรบ้าง และเห็นภาพรวมให้ครบที่สุด

**ตกลงแล้ว**
| เรื่อง | ข้อตกลง |
|---|---|
| "มีคนตอบกี่คน" | นับเฉพาะคนที่ส่งคำตอบสำเร็จ (ไม่นับคนที่เปิดหน้าแล้วออก) |
| ความคิดเห็น | แยกตามคำถาม และค้นคำได้ |
| ส่วนเสริม | ดูคำตอบรายคน + กราฟจำนวนคำตอบรายวัน |
| ไม่ทำ | ตัวกรองช่วงวันที่, ตารางไขว้ |
| แนวทาง | A: รวมผลไว้ใน cache ที่ server แบบเพิ่มทีละส่วน ส่วนความคิดเห็นและรายคนดึงทีละหน้าเมื่อเปิดดู |

**ถือว่าสำเร็จเมื่อ**
1. แท็บภาพรวมแสดงจำนวนคำตอบทั้งหมด แยกตามบทบาท วันนี้ และทางสำรองถูกต้อง พร้อมกราฟรายวัน
2. ทุกข้อคำถามแบบปิดของทั้ง 2 บทบาทมีสรุปเป็นตัวเลขหรือกราฟ
3. ความคิดเห็นทุกข้อ (ข้อความยาว 8 ข้อ + หมายเหตุจุดบนผัง) ดูได้ ค้นคำได้ และกดไปดูคำตอบเต็มของคนนั้นได้
4. แท็บรายคนแสดงคำตอบครบทุกข้อเป็นภาษาไทย
5. การเปิดหน้ายังอ่าน D1 เพียงไม่กี่แถวผ่าน cache ไม่มี polling และหน้าแบบสอบถามไม่เปลี่ยน (visual test เดิมผ่าน)

## 2. หน้าตา (admin.html — 4 แท็บ)

ด้านบนเหมือนเดิม: หัว "สรุปผล" + ปุ่ม [อัปเดต] [ดาวน์โหลด CSV] [ออกจากระบบ] แท็บที่เลือกจำไว้ในหน่วยความจำของหน้าเท่านั้น

### 2.1 ภาพรวม
- **ตัวเลขใหญ่ 6 ช่อง:** คำตอบทั้งหมด · เจ้าหน้าที่ · ผู้บริจาค · วันนี้ (วันที่ตามเวลาไทย) · เข้าทางสำรอง (`src = 1`) · อัปเดตล่าสุด
- **กราฟแท่งรายวัน (SVG):** แกน x คือทุกวันตั้งแต่วันแรกที่มีคำตอบจนถึงวันล่าสุด (วันที่ไม่มีคำตอบแสดงเป็น 0) แท่งซ้อนสีเจ้าหน้าที่/ผู้บริจาค มีตัวเลขรวมของวันนั้นบนแท่ง ถ้าเกิน 31 วันให้เลื่อนแนวนอนได้
- **การ์ดเดิม:** heatmap ผังรถ (แยกแท็บย่อยเจ้าหน้าที่/ผู้บริจาค), แผนภาพร่างกาย, อันดับ
- **การ์ดโควตาวันนี้** (เดิม)
- ถ้ายังไม่มีคำตอบ ทุกการ์ดแสดง "ยังไม่มีข้อมูล"

### 2.2 คำถามทั้งหมด
สลับ [เจ้าหน้าที่ | ผู้บริจาค] แล้วเรียงตามส่วนของบทบาทนั้น หัวข้อแต่ละส่วนใช้ `sec.title` และแต่ละข้อใช้ `q.label` จริง

| ชนิด | แสดง |
|---|---|
| pills | แท่งแนวนอนทุกตัวเลือก (รวมตัวเลือกที่ได้ 0) "จำนวน (x%)" โดย % = จำนวน ÷ คนที่ตอบข้อนี้ ข้อ optional แสดง "ตอบ N จาก M คน" |
| scale | แท่ง 1–5 ใช้ป้ายจากตัวเลือก + "ค่าเฉลี่ย x.x" |
| multi | แท่งทุกตัวเลือก "จำนวน (x%)" โดย % = จำนวน ÷ คนที่ตอบข้อนี้ + หมายเหตุว่า "เลือกได้หลายข้อ ผลรวมเกิน 100% ได้" |
| rank | แท่งคะแนนรวม (เรียงมากไปน้อย) + คอลัมน์ "อันดับ 1 (คน)" |
| number | ค่าเฉลี่ย · มัธยฐาน · ต่ำสุด · สูงสุด (ทศนิยม 1 ตำแหน่ง) + แท่งความถี่ของแต่ละค่า (ไม่เกิน 20 แท่ง ถ้าเกินให้รวมเป็นช่วงเท่ากัน) |
| textarea | "N ความคิดเห็น" + ลิงก์ [ดู] ไปแท็บความคิดเห็นที่ข้อนั้น |
| ส่วน bodyMap | ตาราง: ส่วนร่างกาย · จำนวนคน · 12 เดือน "ใช่" · 7 วัน "ใช่" · ความรุนแรงเฉลี่ย (0–10) + บรรทัด "ไม่มีอาการ N คน" |
| ส่วน busMap | ตาราง: จุด (label ของโซน) · จำนวนคน · ความรุนแรงเฉลี่ย · ประเภทปัญหา 3 อันดับแรก "ชื่อ (n)" · ส่วนของเก้าอี้ 3 อันดับแรก (เฉพาะเก้าอี้) + บรรทัด "ไม่พบปัญหา N คน" |

### 2.3 ความคิดเห็น
- **รายการข้อ (ซ้าย หรือด้านบนบนมือถือ):** ข้อความยาวทั้ง 8 ข้อตามลำดับในแบบสอบถาม (เจ้าหน้าที่: `rowdiff`, `cleanspot`, `material`, `setup`, `faint`, `worry`, `other` / ผู้บริจาค: `improve`) + "หมายเหตุจุดบนผัง" (`map`) แต่ละข้อมีจำนวนความคิดเห็นจาก cache กำกับ
- **การ์ดความคิดเห็น:** ข้อความเต็ม (ขึ้นบรรทัดตามที่พิมพ์) · บทบาท · เวลาไทย · ชื่อจุด (ถ้าเป็นหมายเหตุจุดบนผัง) · ลิงก์ "ดูคำตอบทั้งหมดของคนนี้" ซึ่งพาไปแท็บรายคนที่ `id` นั้น
- **ค้นหา:** ช่องค้นคำ + ปุ่ม [ค้นหา] / [ล้าง] ค้นเฉพาะข้อที่เลือก
- **โหลดเพิ่ม:** ครั้งละ 50 รายการ ใหม่สุดก่อน มีปุ่ม [โหลดเพิ่ม] เมื่อ `next` ไม่เป็น null
- ไม่มีผลลัพธ์ → "ไม่พบความคิดเห็น"

### 2.4 รายคน
- **ตาราง:** ครั้งละ 50 คน ใหม่สุดก่อน คอลัมน์ ลำดับ (`id`) · เวลาไทย · บทบาท · ช่องทาง (ตรง/ทางสำรอง) มีตัวกรอง [ทั้งหมด | เจ้าหน้าที่ | ผู้บริจาค] และปุ่ม [ใหม่กว่า] [เก่ากว่า]
- **รายละเอียด:** กดแถว (หรือมาจากลิงก์ในความคิดเห็น) เพื่อเปิดหน้ารายละเอียด พร้อมปุ่ม [กลับไปรายการ]
  - หัว: ลำดับ · เวลา · บทบาท · ช่องทาง
  - เรียงตามส่วน: "คำถาม → คำตอบ"
    - scale แสดงป้ายตัวเลือก
    - multi และ rank แสดงเป็นรายการ (rank ใส่ลำดับ 1–3 ด้วย)
    - ข้อ optional ที่ไม่ได้ตอบแสดง "—"
  - ส่วน C: ตาราง ส่วนร่างกาย · 12 เดือน · 7 วัน · ความรุนแรง หรือ "ไม่มีอาการปวดเมื่อย"
  - ส่วน D: ตาราง จุด · ประเภท · ส่วนของเก้าอี้ · ความรุนแรง · หมายเหตุ หรือ "ไม่พบปัญหา"

### 2.5 สีและการเข้าถึง
- สีเจ้าหน้าที่ใช้ `blood` (#b83227) ส่วนผู้บริจาคใช้สีที่สองซึ่งต่างกันชัดทั้งค่าความสว่างและเฉดสี โดยเลือกตาม skill dataviz ตอนลงมือ และกำหนดเป็นค่าเดียวใน `tailwind.config.js`
- ทุกแท่งมีตัวเลขกำกับ
- ตารางมี `<th scope>`
- ข้อความทั้งหมดของผู้ตอบผ่าน `App.ui.esc()`

## 3. Server

### 3.1 cache ผลสรุปรุ่น 2 (`src/summary.js`)
`emptyAcc()` คืนค่าที่มี `v: 2` และค่าต่อบทบาทดังนี้ (ใช้ `Object.hasOwn` และรับเฉพาะ key หรือตัวเลือกที่อยู่ใน `SCHEMA`/`ZONES`/`BODY_REGIONS` เหมือนเดิม)

```js
{
  v: 2,
  staff: {
    n, src1,                         // จำนวนคำตอบ, จำนวนที่มาจาก Sheets
    days: { '2026-10-31': n },       // วันที่ตามเวลาไทยจาก created
    heat: { zone: { c, s } },        // เดิม
    body: { region: n },             // เดิม
    rank: { opt: points },           // เดิม
    rank1: { opt: n },               // จำนวนครั้งที่เป็นอันดับ 1
    q: { key: { opt: n } },          // pills / scale (key ของตัวเลือกเป็น String) / multi / rank (นับการถูกเลือก)
    num: { key: { value: n } },      // number: ความถี่ของค่า (value เป็น string ตามที่เก็บ)
    msd: { region: { n, y, w, s: { '0'..'10': n } } },
    noMsd,
    zt: { zone: { type: n } },       // ประเภทปัญหาต่อจุด
    zp: { zone: { part: n } },       // ส่วนของเก้าอี้ต่อจุด
    noMap,
    text: { key: n },                // จำนวนความคิดเห็นต่อข้อความยาว
    notes                            // จำนวนจุดที่มีหมายเหตุ (n ไม่ว่าง)
  },
  donor: { /* โครงเดียวกัน; body/rank/rank1/msd/noMsd ว่างเสมอ */ }
}
```

- `present(acc)` คืนรูปแบบเดิมครบ (`staff: {n, heat, body, rank}`, `donor: {n, heat}`) และเพิ่มฟิลด์ต่อบทบาท: `src1`, `days: [[date, n], ...]` (เรียงวันที่), `q`, `rank1`, `num`, `msd: {region: {n, y, w, avg, dist: [11 ค่า]}}`, `noMsd`, `zones: {zone: {t: [[type, n]...], p: [[part, n]...]}}` (เรียงมากไปน้อย), `noMap`, `text`, `notes` สถิติ (เฉลี่ย, มัธยฐาน) คำนวณที่หน้าเว็บจาก `num`/`q`
- **อัปเกรด:** ใน `GET /api/admin/summary` ถ้า `stored.data` ไม่มี `v === 2` ให้ทำเหมือน `rebuild=1` (เริ่มจาก `emptyAcc()` และ `last_id = 0`)
- **การจำกัดต่อรอบ:** ยังรวมครั้งละ 100 แถว และส่ง `more` เหมือนเดิม

### 3.2 endpoint
ทุก route อยู่ใต้ `adminRoutes` (ผ่าน `requireAdmin`, `no-store`, `noindex`) และจบด้วย `bumpUsage(n=0)`

**`GET /api/admin/comments?key=&role=&q=&before=&limit=`**
- **ตรวจพารามิเตอร์:**
  - `key` ต้องเป็นข้อความยาวที่อยู่ใน `SCHEMA` (หาจาก `type === 'textarea'`) หรือ `map` ถ้าไม่ใช่ → 400 `{error:'invalid', field:'key'}`
  - `role` ต้องเป็น `staff|donor` หรือไม่ใส่ (ข้อความยาวผูกกับบทบาทอยู่แล้ว ส่วน `map` ใช้ได้ทั้งคู่)
  - `before` เป็น id (ไม่ใส่ = ใหม่สุด)
  - `limit` 1–100 (ค่าเริ่มต้น 50)
  - `q` เป็น string ยาวไม่เกิน 100 (ตัดช่องว่างหัวท้ายก่อน)
- **ข้อความยาว:** `SELECT id, role, created, json_extract(data, '$.answers.<key>') AS text FROM responses WHERE id < ? [AND role = ?] AND text IS NOT NULL [AND instr(text, ?) > 0] ORDER BY id DESC LIMIT ?` (`<key>` มาจากรายการที่ตรวจแล้วเท่านั้น)
- **`map`:** แบ่งหน้าตามคนเพื่อไม่ให้หมายเหตุของคนเดียวถูกตัดครึ่ง
  - ขั้นที่ 1: `SELECT id FROM responses WHERE id < ? [AND role = ?] AND json_extract(data, '$.map') <> '{}' ORDER BY id DESC LIMIT ?` → รายการ id
  - ขั้นที่ 2: `SELECT r.id, r.role, r.created, j.key AS zone, json_extract(j.value, '$.n') AS text FROM responses r, json_each(r.data, '$.map') j WHERE r.id IN (<id จากขั้นที่ 1>) AND text <> '' [AND instr(text, ?) > 0] ORDER BY r.id DESC, j.key`
  - `next` = id ที่น้อยที่สุดจากขั้นที่ 1 เมื่อได้ครบ limit ไม่เช่นนั้น null
  - เมื่อมี `q` ให้ข้ามขั้นที่ 1 แล้วค้นทุกแถวในขั้นเดียว (`WHERE r.id < ? … AND instr(text, ?) > 0 ORDER BY r.id DESC, j.key LIMIT ?`) โดย `next` = id ของรายการสุดท้ายถ้าได้ครบ limit
- **ผลลัพธ์ (ทั้งสองแบบ):** `{ items: [{id, role, created, text, zone?}], next }` โดยสำหรับข้อความยาว `next` = id ของรายการสุดท้ายถ้าได้ครบ limit ไม่เช่นนั้น null

**`GET /api/admin/responses`** เพิ่ม `before`
- ถ้ามี `before` (จำนวนเต็ม ≥ 1) → `WHERE id < ? … ORDER BY id DESC` และ `next` = id ของแถวสุดท้ายถ้าได้ครบ limit
- ห้ามส่ง `after` กับ `before` พร้อมกัน (ส่งมา → 400 field `before`)
- `after` แบบเดิมไม่เปลี่ยน (CSV ยังใช้)

**`GET /api/admin/responses/:id`** → `{row: {id, cid, role, created, src, data}}` ถ้าไม่มี → 404 `{error:'not_found'}` และ id ที่ไม่ใช่จำนวนเต็มบวก → 400

### 3.3 ต้นทุน
| การกระทำ | คำขอ | อ่าน D1 | เขียน D1 |
|---|---|---|---|
| เปิดหรืออัปเดตภาพรวม | 1 (+1 ต่อ 100 คำตอบใหม่) | 4 + คำตอบใหม่ | 2 |
| ความคิดเห็น 1 หน้า | 1 | ≈ 50–100 | 1 |
| ค้นหาความคิดเห็น | 1 | ทุกแถวของบทบาทนั้น (≈ 4,600 ที่ 3 เดือน) | 1 |
| รายคน 1 หน้า / 1 คน | 1 | ≈ 50 / 1 | 1 |

ประมาณการ (เปิด 10 ครั้ง + ดู 20 หน้า + ค้น 2 ครั้งต่อวัน): อ่านไม่ถึง 12,000 แถว/วัน (< 0.3%) และเขียนไม่ถึง 60 แถว/วัน

## 6. สมมติฐานและข้อควรระวัง
1. "วันนี้" และกราฟรายวันใช้วันที่ตามเวลาไทย (UTC+7) ซึ่งต่างจากวันของโควตาที่ใช้ UTC
2. การค้นหาความคิดเห็นอ่านทุกแถวของบทบาทนั้น ถ้าข้อมูลโตมาก (เช่น 100,000 คำตอบ) จะอ่าน 100,000 แถวต่อการค้น (2% ของโควตาอ่านต่อวัน) จึงควรค้นเท่าที่จำเป็น
3. ข้อความคำถามในหน้าแอดมินมาจากไฟล์คำถามชุดเดียวกับแบบสอบถาม ถ้าแก้ข้อความคำถามระหว่างเปิดรับ คำตอบเก่าจะแสดงใต้ข้อความใหม่ (ส่วน key และตัวเลือกยังตรวจด้วย schema-sync test)
4. ตัวเลือกที่ถูกลบออกจากไฟล์คำถามภายหลังจะไม่แสดงในกราฟ (นับเฉพาะตัวเลือกที่ยังอยู่ใน `SCHEMA`)
